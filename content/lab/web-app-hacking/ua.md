## Що знадобиться

- **Docker**: інструмент, який запускає кожен застосунок в окремому контейнері (невеликій відокремленій «коробці» на
  вашому комп'ютері). На Windows і macOS це Docker Desktop (інструкції для [Windows](/en/guides/install-docker-desktop/)
  і [Mac](/en/guides/install-docker-desktop-mac/)), на Linux — Docker Engine із плагіном Compose
  ([інструкція](/en/guides/install-docker-engine-linux/)).
- **Кілька гігабайтів вільного місця на диску** для застосунків. Вони завантажуються під час першого запуску.
- **Burp Suite Community Edition**: безкоштовний інструмент, який показує кожен запит вашого браузера. Він
  знадобиться лише в розділі «Стежте за трафіком».

## Що є в лабораторії

| Застосунок | Що ви тренуєте | Порт |
|---|---|---|
| OWASP Juice Shop | Інтернет-магазин із вразливостями з усього OWASP Top 10 і багатьма іншими | 3000 |
| OWASP WebGoat | Короткі уроки: спершу пояснення вразливості, потім спроба нею скористатися | 8081, 9090 |
| VAmPI | Невеликий REST API з вразливостями з OWASP API Security Top 10 | 5001 |
| DVGA | Атаки на GraphQL API, у режимі для початківців і для експертів | 5013 |

## Завантажте файл

1. Створіть папку для лабораторії, наприклад `practice-lab`, і відкрийте в ній термінал.
2. Завантажте файл, який описує лабораторію:

   ```sh
   curl -O https://lvlulcuma.com/lab/web-app-hacking/compose.yaml
   ```

   У PowerShell на Windows пишіть `curl.exe` замість `curl`:

   ```powershell
   curl.exe -O https://lvlulcuma.com/lab/web-app-hacking/compose.yaml
   ```

3. Прочитайте його, перш ніж запускати. Він короткий, а читати файли з інтернету перед запуском — корисна звичка. Ось
   увесь файл:

   ```yaml
   #include public/lab/web-app-hacking/compose.yaml
   ```

   > [!NOTE]
   > Кожен рядок під `ports:` починається з `127.0.0.1`. Саме завдяки цьому застосунки доступні лише з вашого комп'ютера.

## Запустіть

1. У тій самій папці виконайте:

   ```sh
   docker compose up -d
   ```

   Під час першого запуску завантажуються всі чотири застосунки, тож це займе кілька хвилин. `-d` залишає їх
   працювати у фоні.
2. Перевірте, що всі працюють:

   ```sh
   docker compose ps
   ```

   У стовпці `STATUS` біля кожного застосунку має бути `Up`. WebGoat додає `(healthy)`, коли буде готовий, приблизно
   за хвилину.

## Відкрийте кожен застосунок

1. **Juice Shop:** відкрийте `http://127.0.0.1:3000`. У магазині є прихована таблиця результатів (score board), яка
   відстежує ваш прогрес, і знайти її — перше завдання.
2. **WebGoat:** відкрийте `http://127.0.0.1:8081/WebGoat` і створіть обліковий запис. Ім'я має містити від 6 до 45 малих
   латинських літер, цифр або дефісів, а пароль — від 6 до 10 символів. Обліковий запис існує лише всередині застосунку.
   WebWolf, його помічник із тестовою поштовою скринькою та завантаженням файлів, працює за адресою
   `http://127.0.0.1:9090/WebWolf`.
3. **VAmPI:** один раз відкрийте `http://127.0.0.1:5001/createdb`. Це заповнить базу даних тестовими користувачами й
   книжками. Потім відкрийте `http://127.0.0.1:5001/ui/`: там сторінка з переліком усіх ендпоінтів API.
4. **DVGA:** відкрийте `http://127.0.0.1:5013`. Почніть із режиму для початківців; режим для експертів робить ті самі
   атаки складнішими.

## Стежте за трафіком у Burp Suite

1. Встановіть [Burp Suite Community Edition](https://portswigger.net/burp/communitydownload) і запустіть його з
   налаштуваннями за замовчуванням.
2. Перейдіть у **Proxy > Intercept** і натисніть **Open browser**. Цей браузер надсилає все через Burp, зокрема
   й трафік на `127.0.0.1`, тож нічого налаштовувати не потрібно.
3. Відкрийте в цьому браузері один із застосунків і погляньте на **Proxy > HTTP history**: там кожен запит і кожна
   відповідь. Клацніть запит правою кнопкою й виберіть **Send to Repeater**, щоб змінити його й надіслати ще раз.

> [!TIP]
> Якщо сторінки перестали завантажуватися, увімкнено **Intercept**: він затримує кожен запит, доки ви не натиснете
> **Forward**. Вимкніть його, коли хочете лише спостерігати.

> [!NOTE]
> Burp слухає `127.0.0.1:8080`. Тому WebGoat у цій лабораторії використовує порт 8081.

## Тримайте лабораторію ізольованою

1. **Залишайте `127.0.0.1` у кожному рядку з портом.** Без нього Docker відкриє порт у кожній мережі, до якої
   підключений ваш комп'ютер, зокрема у Wi-Fi кав'ярні. На Linux такий порт навіть обходить правила фаєрвола,
   створені через ufw.
2. **Ніколи не запускайте лабораторію на сервері**, у хмарі чи на спільному комп'ютері.
3. **Зупиняйте її, коли закінчили**, командою `docker compose down`. Вимкнений вразливий застосунок неможливо атакувати.
4. **Не вводьте в застосунки справжні паролі чи особисті дані.** Використовуйте вигадані імена, як-от `test-user`.

## Скидання й оновлення

1. Щоб почати спочатку, виконайте `docker compose down`, а потім `docker compose up -d`. Усе, що ви змінили всередині
   застосунків, зникне, і вони запустяться з нуля.
2. Щоб отримати найновіші версії, виконайте `docker compose pull`, а потім `docker compose up -d`.
3. Щоб повністю видалити лабораторію, виконайте `docker compose down --rmi all`. Це видалить і завантажені застосунки.

## Додайте crAPI (за бажанням)

OWASP crAPI — більший навчальний застосунок: сайт для власників автомобілів із магазином, зв'язком із механіком
і поштовою скринькою, зібраний із багатьох контейнерів. Він має власний compose-файл, тож працює поруч із цією
лабораторією, а не всередині неї.

1. Завантажте й запустіть його командами з його власної інструкції:

   ```sh
   curl -L -o crapi.zip https://github.com/OWASP/crAPI/archive/refs/heads/main.zip
   unzip crapi.zip
   cd crAPI-main/deploy/docker
   docker compose pull
   docker compose -f docker-compose.yml --compatibility up -d
   ```

   На Windows пишіть `curl.exe` замість `curl` і `tar -xf crapi.zip` замість `unzip crapi.zip`.
2. Відкрийте `http://127.0.0.1:8888`. Його листи надходять у тестову поштову скриньку за адресою `http://127.0.0.1:8025`.

> [!WARNING]
> crAPI теж за замовчуванням прив'язаний до `127.0.0.1` завдяки рядку `LISTEN_IP` у його файлі `.env`. Його інструкція
> показує, як змінити це на `0.0.0.0`; для навчальної лабораторії цього не робіть.

## Якщо щось пішло не так

1. **«port is already allocated»:** цей порт уже зайняла інша програма. Змініть у цьому рядку перше число після
   `127.0.0.1:`, наприклад на `"127.0.0.1:3001:3000"`, і відкривайте застосунок на новому порту.
2. **Застосунок не запускається на комп'ютері з ARM** (наприклад, на Mac з Apple silicon): деякі образи зібрані лише
   для x86. У налаштуваннях Docker Desktop увімкніть **Use Rosetta for x86_64/amd64 emulation on Apple Silicon**
   і додайте `platform: linux/amd64` під рядком `image:` цього застосунку. Стаття нижче пояснює це докладно.
3. **WebGoat не відкривається одразу після запуску:** йому потрібна приблизно хвилина. Зачекайте, доки
   `docker compose ps` покаже `(healthy)`.
4. **VAmPI відповідає помилкою або порожнім списком:** спершу відкрийте `/createdb` (див. «Відкрийте кожен застосунок»).
5. **Щось інше:** `docker compose logs juice-shop` (або `webgoat`, `vampi`, `dvga`) покаже, що цей застосунок вивів
   під час запуску.
